# 방법 비교: 기존 지형 생성 방법과 B-PCG 견주기

> "B-PCG가 더 지구답다"고 말하려면, 기존 방법과 같은 조건에서 나란히 놓고 재야 합니다. 이 도구는 지형 생성 논문 리뷰(Galin 외 2019)가 대표로 꼽은 방법 10개와 B-PCG를 같은 크기의 땅, 같은 출발 번호(시드)로 돌립니다. 그다음 같은 지표로 재고, 같은 빛과 색으로 그립니다. 방법마다 지형을 만드는 중간 과정도 남겨 한 장씩 볼 수 있습니다. 단, 비교하는 것은 한 변 12.8 km 평면 한 장의 높이뿐입니다.

## 직접 돌려 보기

### 1. 작은 비교 한 번

```bash
uv run bpcg compare run --param grid.n=64 --seeds 0 --out out/compare/try
```

- 방법 12개(같은 방법을 매개변수만 바꾼 변형 하나 포함)를 64 × 64칸, 시드 0으로 한 번씩 돌립니다.
- 맞게 돌았으면: 마지막 줄이 `[비교] 끝: 0.6 s → out/compare/try` 처럼 나옵니다.
- 걸리는 시간: 약 2초(맥북 에어 M3, C# 빌드가 끝난 뒤).

### 2. 결과 표 보기

```bash
uv run bpcg compare list --set try
```

- `== 시드 0` 아래에 방법마다 한 줄씩 생성 시간과 지표 12개가 나옵니다.

### 3. 그림 한 장 그리기

```bash
uv run bpcg compare render --set try --seed 0 --method bpcg
```

- 그린 PNG 파일의 경로가 한 줄 나옵니다. 그림은 한 번에 한 장씩만 그립니다.

### 4. 기본 설정으로 돌리고 화면에서 보기

```bash
uv run bpcg compare run      # configs/compare/default.toml → out/compare/default
uv run bpcg studio           # 위 막대 '방법 비교'
```

- 기본 설정은 256 × 256칸(칸 50 m), 시드 3개, 방법 12개입니다. 약 12초가 걸리고, 대부분은 `stream_power`(시드마다 약 2초)입니다.

| 다른 명령 | 하는 일 |
|---|---|
| `uv run bpcg compare methods` | 등록된 방법과 매개변수 목록 (`--json` 이면 JSON) |
| `uv run bpcg compare list --set default --json` | 결과를 JSON으로 |
| `uv run bpcg compare render … --stage 3` | 연산 과정의 3번 단계 그림 |

## 무엇을 같게 맞추나

공정하게 견주려면 방법 말고는 모든 것이 같아야 합니다.

- **같은 땅 크기.** 모든 방법이 같은 n × n 평면에 높이를 냅니다. 기본은 256 × 256칸, 칸 50 m, 한 변 12.8 km입니다. 서울 남북 길이(30 km)의 절반쯤 되는 네모입니다.
- **같은 시드끼리 묶기.** 결과는 `out/compare/<이름>/seed_NNNN/<방법>/` 에 쌓입니다. 표와 화면은 시드마다 모든 방법을 한 묶음으로 보여 줍니다. 그래서 "시드 0의 fbm과 시드 0의 B-PCG"처럼 같은 출발점끼리 견줍니다.
- **같은 잣대.** 지표는 모든 높이 지도에 같은 코드로 잽니다. 물길도 방법이 만든 것을 쓰지 않고, 네 가장자리를 출구로 둔 같은 규칙(D8)으로 다시 셉니다.
- **같은 그림.** 같은 빛(북서쪽 315°, 높이 45°), 같은 과장(1배), 같은 색표로 그립니다.

## 비교하는 방법

방법은 세 갈래로 나뉩니다.

- **절차적 생성.** 무작위 수와 수식만으로 높이를 만듭니다. 빠르지만 왜 그 모양인지 원인이 없습니다.
- **시뮬레이션.** 물과 흙이 움직이는 규칙을 시간 순서로 돌려 지형을 깎습니다.
- **예제 기반.** 진짜 지형 조각을 이어 붙입니다.

| id | 갈래 | 화면에서 보이는 것 | B-PCG와 다른 점 |
|---|---|---|---|
| `fbm` | 절차적 | 크기가 다른 무작위 물결을 겹친 언덕. 어디나 비슷하게 거침 | 원인이 없고 물길이 이어지지 않음 |
| `ridged` (+ `ridged_sharp`) | 절차적 | 물결을 뒤집어 만든 날카로운 산마루 | 위와 같음 |
| `multifractal` | 절차적 | 낮은 곳은 매끈한 평야, 높은 곳은 거친 산 | 위와 같음 |
| `warped` | 절차적 | 좌표를 비틀어 흐르는 듯한 무늬 | 깎인 것처럼 보이기만 하고 흙이 옮겨 가지 않음 |
| `diamond_square` | 절차적 | 칸을 반씩 나누며 높이를 흔든 흔적(네모난 무늬) | 원인이 없음 |
| `faulting` | 절차적 | 무작위 직선을 따라 한쪽이 솟은 계단 | 원인이 없음 |
| `thermal` | 시뮬레이션 | fbm에서 너무 가파른 비탈만 무너뜨림 | 노이즈 지형을 꾸미는 후처리 |
| `hydraulic` | 시뮬레이션 | fbm 위로 물방울을 굴려 깎고 쌓음(칸마다 1.5개, 256 × 256칸이면 약 10만 개). 게임에서 흔함 | 땅이 솟지 않고 깎이기만 함 |
| `stream_power` | 시뮬레이션 | 땅이 솟는 동안 강이 깎는 것을 수백만 년 동안 시간 순서로 계산 | 가장 가까운 기존 방법. 암석 한 종류, 땅속 없음, 다 자란 모양을 바로 풀지 않음 |
| `quilting` | 예제 기반 | 진짜 지형(가봉 로페, 30 m 간격) 조각을 이음매가 가장 덜 보이게 이어 붙임 | 조각 안은 진짜지만 물길이 이어진다는 보장이 없음 |
| `bpcg` | 우리 | 융기 → 지층마다 다른 경사로 다 자란 모양 → 물·흙·지하수·동굴 | — |

- **절차적 방법의 높이.** 이 방법들은 높이 단위가 없습니다. 그래서 가장 높은 곳과 낮은 곳의 차이를 `grid.relief_m`(기본 1,500 m, 한라산보다 조금 낮음)에 맞춥니다.
- **침식 방법의 시작 지형.** `thermal`·`hydraulic` 은 같은 시드의 `fbm` 에서 시작합니다. 그래서 묶음 안에서 깎기 전과 후를 바로 견줄 수 있습니다.
- **`stream_power` 의 조건.** B-PCG 평면 히어로와 같은 융기(북쪽 산맥)와 출구(남쪽 가운데 5칸)를 씁니다. 같은 조건에서 '시간 순서로 계산'과 '다 자란 모양을 바로 풀기'를 견줍니다.
- **넣지 않은 방법.** 신경망 방법(논문 5.3)과 희소 모델(5.4)은 학습 자료와 가중치가 필요해 넣지 않았습니다. 설계도도 신경망을 쓰지 않기로 했습니다. 격자 위 물 흐름으로 깎는 방법(4.3.1)과 스케치로 그리는 방법(3.2)은 아래 '방법 더하기'로 넣을 수 있습니다.

## 결과 폴더

```text
out/compare/<이름>/
  compare.json                    설정 전체(땅 크기, 시드, 방법과 매개변수), 지표 설명, 고친 때, 코드 판
  seed_0000/<id>/z.npy            높이 (n, n) float32 [m]
                 meta.json        방법, 매개변수, 시드, 생성 시간, 높이 범위, 진단값
                 metrics.json     지표
                 layers/*.npy     덧붙인 지도 (B-PCG의 지하수면·강·지표 암석 등)
                 stages/NN.npy    연산 과정의 중간 지도. stages.json 에 이름·종류·설명·범례
                 trace.json       반복마다 바뀐 값(곡선)과 단계별 값(막대)
                 *.png            그림 (필요할 때 한 장씩 만듦)
```

- **같은 입력이면 같은 결과.** 무작위 값은 모두 정수 해시로 만듭니다. 그래서 같은 땅 크기·시드·매개변수면 어느 컴퓨터에서든 같은 높이가 나옵니다. 연산 과정을 기록해도 높이는 비트까지 같습니다.
- **한 번 만든 것은 다시 만들지 않음.** 매개변수·땅 크기·시드·기록 여부·코드 판이 같으면 저장해 둔 것을 씁니다(로그에 `(캐시)`). `--force` 를 붙이면 늘 다시 만듭니다.
- **땅 크기는 묶음마다 하나.** 한 묶음 폴더에는 같은 땅 크기의 결과만 들어갑니다. 크기를 바꾸면 `--out` 으로 다른 폴더를 줍니다.

<details><summary>자세한 규칙: 코드 판, 시간 재기, Python 판과의 대조</summary>

- **코드 판.** `Bpcg` 어셈블리의 모듈 ID입니다. 빌드가 결정적이라 소스가 같으면 같습니다. 라이브러리 어디든 고치면 모든 방법을 다시 만듭니다(보수적이지만 기본 설정도 다시 만드는 데 약 12초).
- **지표 입력.** 지표는 저장한 float32 높이로 잽니다. 새로 만들 때와 저장본을 읽을 때 지표가 같게 하려는 것입니다.
- **시간.** `meta.json` 의 `seconds` 는 연산 과정 기록에 든 시간을 뺀 생성 시간이고, `wall_seconds` 는 기록을 포함한 시간입니다. 방법을 처음 쓸 때 32 × 32로 한 번 미리 돌려, 첫 실행의 준비 시간(JIT)이 섞이지 않게 합니다.
- **Python 판과 같음.** C#으로 옮기기 전 Python 판과 n = 64·96, 시드 0·7에서 12개 방법의 높이와 연산 과정 지도가 비트까지 같음을 확인했습니다(2026-10-08). 옮기며 고친 것은 둘입니다. 스펙트럼 β는 numpy와 같은 평면 전체 평균으로 셉니다. 지표는 float32 높이로 잽니다(Python 판은 새로 만들 때 float64로 재서, 웅덩이 점 수가 저장본과 달랐음).

</details>

## 방법 더하기와 고치기

### 매개변수만 바꾼 변형

설정 TOML에 줄을 더합니다. 코드는 고치지 않습니다.

```toml
[[methods]]
id = "fbm_rough"          # 결과 폴더 이름 (소문자·숫자·_·-)
method = "fbm"            # 등록된 방법 (bpcg compare methods 로 목록 보기)
params = { gain = 0.7, octaves = 10 }
```

명령줄에서 한 번만 바꿀 때는 `--param fbm.octaves=6`, `--param grid.n=128`, `--param run.snapshots=false`(연산 과정을 남기지 않음)를 씁니다.

### 새 방법

`src/Bpcg/Compare/` 에 C# 파일을 하나 만들고, `MethodRegistry.Builtins()` 에 한 줄을 더합니다. 아래는 칸마다 무작위 높이를 주고 이웃 평균으로 다듬는 방법의 전체 코드입니다.

```csharp
using Bpcg.Core;

namespace Bpcg.Compare;

/// <summary>대조군: 칸마다 독립인 무작위 높이를 이웃 평균으로 다듬습니다.</summary>
public static class WhiteNoiseMethod
{
    private const long Stream = NoiseMethods.StreamBase + 901; // 다른 방법과 겹치지 않는 해시 용도 번호

    public static readonly CompareMethod WhiteNoise = new(
        "white_noise",
        "흰 노이즈",
        "procedural", // procedural | simulation | example | ours
        "대조군",
        "칸마다 독립인 무작위 높이",
        [new Param("smooth", 0L, "이웃 평균을 몇 번", Kind: "int", Lo: 0, Hi: 50)],
        (grid, seed, p, ctx) =>
        {
            int n = grid.N;
            double[] z = new double[grid.Cells];
            for (int c = 0; c < z.Length; c++)
            {
                z[c] = Hashing.HashUnit(seed, c, Stream);
            }
            for (int k = 0; k < p.I("smooth"); k++)
            {
                double[] s = new double[z.Length];
                for (int j = 0; j < n; j++)
                {
                    for (int i = 0; i < n; i++)
                    {
                        s[(j * n) + i] = 0.25 * (z[(((j + 1) % n) * n) + i] + z[(((j + n - 1) % n) * n) + i]
                            + z[(j * n) + ((i + 1) % n)] + z[(j * n) + ((i + n - 1) % n)]);
                    }
                }
                z = s;
                ctx.Snapshot($"{k + 1}번 평균", z, note: "이웃 평균을 한 번 더 한 지형"); // 과정 기록
            }
            return new MethodOutput(CompareGrid.NormalizeRelief(z, grid.ReliefM));
        });
}
```

지켜야 할 약속은 네 가지입니다.

1. **꼴.** `Generate(grid, seed, params, ctx)` 가 높이 배열을 담은 `MethodOutput` 을 돌려줍니다. 높이는 칸 n × n개를 한 줄로 늘어놓은 배열이고(0번 줄이 북쪽), 모든 값이 유한해야 합니다. 덧붙인 지도는 `output.Layers`, 진단값은 `output.Info` 에 넣습니다.
2. **같은 입력이면 같은 출력.** 무작위 값은 `Hashing.Hash3`·`HashUnit` 같은 정수 해시로만 만듭니다(`System.Random` 금지). 칸마다 서로 독립인 일만 `Parallelism.For` 로 나눕니다.
3. **연산 과정 기록.** `ctx.Snapshot(이름, 배열, kind, note, unit, scale)` 로 중간 지도를 남깁니다.
    - `kind` 는 그리는 방식입니다: `height` 높이, `field` 값, `log` 로그 값, `diverging` 늘고 준 양, `mask` 표시(높이 그림 위), `category` 종류.
    - `scale` 은 색 범위입니다: `self` 는 이 지도의 범위, `final` 은 최종 높이의 범위(여러 단계의 높이를 같은 색으로 볼 때).
    - `ctx.Trace(이름, x, y, …)` 는 반복 곡선, `ctx.Bar(이름, [(항목, 값)], …)` 는 막대입니다.
    - 기록만을 위한 계산은 `using (ctx.Extra()) { … }` 안에 두면 생성 시간에서 빠집니다.
    - 기록을 켜도 높이가 바뀌면 안 됩니다. 기록 여부에 따라 실수를 더하는 순서가 바뀌지 않게 합니다(`FaultingMethod` 의 고정된 끊는 점 참고).
4. **시험.** `dotnet test --solution Bpcg.slnx` 가 새 방법도 저절로 검사합니다: 같은 시드면 같은지, 시드가 다르면 다른지, 기록해도 같은지(`CompareToolTests`).

### 새 지표

`src/Bpcg/Compare/CompareMetrics.cs` 의 `All` 에 `new("이름", "표시 이름", "단위", "묶음", "설명", 함수)` 를 더합니다. 함수는 높이, 채운 높이, 물을 보내는 이웃, 상류 면적, 경사, 강 칸을 담은 `Analysis` 를 받습니다. 잴 수 없으면 NaN을 돌려주면 표에 '-' 로 나옵니다.

## 화면 (스튜디오 → 방법 비교)

| 부분 | 하는 일 |
|---|---|
| 위 막대 | 비교 묶음 고르기, 땅 크기 |
| 왼쪽 '시드 묶음' | 시드마다 모든 방법(갈래 색 점, 생성 시간). 누르면 가운데에 그 결과 |
| 높이 그림 | 그림 **한 장**. 색 범위를 '이 지형' 또는 '같은 시드 묶음'으로 고릅니다. ◀▶ 같은 시드의 다른 방법, ▲▼ 같은 방법의 다른 시드 |
| 지표 | 그 시드 묶음의 방법 × 지표 표. 머리글에 마우스를 올리면 뜻이, 줄을 누르면 그 방법이 나옵니다 |
| 연산 과정 | 단계 단추와 슬라이더로 중간 지도를 한 장씩(종류별 범례와 설명), 아래에 반복 곡선과 단계 막대 |
| 왼쪽 '비교 실행' | 설정·묶음 이름·시드·방법·땅 크기를 정해 비교를 돌립니다(먼저 C# 빌드). 진행 막대와 기록 |

키보드: ←/→ 방법, ↑/↓ 시드, [ / ] 과정 단계.

그림은 한 번에 한 장만 그립니다.

- 서버는 그림 명령(`bpcg compare render`)을 한 번에 하나씩 부릅니다.
- 한 번 그린 그림은 경로를 기억합니다. 그림 파일이 높이 파일보다 새것이면 다시 그리지 않습니다.
- 그리는 중에 다른 것을 누르면 마지막으로 누른 것만 이어서 그립니다.

방법마다 남기는 연산 과정은 이렇습니다.

| 방법 | 중간 지도 | 곡선·막대 |
|---|---|---|
| 노이즈 갈래 | 물결을 1, 2, 3, 4, 6겹… 더한 지형 (최종 높이 색) | 겹마다 세기와 파장 |
| warped | 비틀기 전 fBm, 좌표를 옮긴 거리, 결과 | — |
| diamond_square | 나눌 때마다 채운 점들 | 나누기마다 흔든 크기 |
| faulting | 직선 1, 3, 10, 30, 100, 300…개 | 직선마다 솟은 크기 |
| thermal | 시작 → 1, 5, 15, 30, 60번 반복 → 높이 변화 | 반복마다 옮긴 칸 수 |
| hydraulic | 시작 → 물방울 1/64·1/16·1/4·1/2·전부 → 높이 변화 | 깎은·쌓은 부피 누적 |
| stream_power | 융기 지도, 처음 지형, 1/16·1/8·1/4·1/2 시점, 최종, 상류 면적 | 가장 크게 변한 속도, 평균·최고 높이 |
| quilting | 예제, 조각 줄마다, 완성, 어느 조각을 붙였나 | 조각마다 이음매 오차 |
| bpcg | 융기 → 미리 푼 지표 → 깎인 두께 → 거친 격자로 먼저 푼 지형 → 솔버 결과 → 유량 → 드러난 암석 → 선상지 → 강·호수 → 흙 → 지하수면 깊이 → 동굴 층 | 솔버 반복마다 방향이 바뀐 칸·가장 크게 변한 높이·묶은 칸, 단계별 시간 |

`bpcg` 의 중간 지도 둘(미리 푼 지표, 거친 격자로 먼저 푼 지형)은 `Flat.FlatHero` 의 `capture` 갈고리로 받습니다. 갈고리를 주지 않으면 계산은 그대로입니다.

## 지표

지표는 두 묶음입니다. '모양'은 높이 분포를, '물길'은 물이 바다까지 잘 빠지는지를 봅니다.

| 지표 | 무엇을 재나 | 읽는 법 |
|---|---|---|
| 기복 [m] | 가장 높은 곳 − 가장 낮은 곳 | 절차적 방법은 `relief_m` 에 맞춘 값이라 비교 대상이 아님 |
| 고도 적분 | (평균 높이 − 최저) ÷ 기복 | 0.5면 평균이 한가운데. 0.3이면 대부분 낮고 일부만 높은 땅(오래 깎인 땅), 0.6이면 높은 땅이 넓음(젊은 산지). 지구는 보통 0.3~0.6 |
| 평균 경사, 경사 90% [°] | 칸마다 경사의 평균, 가파른 쪽에서 10%에 드는 경사 | 경사 90%가 45°면 땅의 10%가 45°보다 가파름 |
| 스펙트럼 기울기 β | 큰 무늬와 작은 무늬의 세기가 얼마나 빨리 줄어드는지 | 클수록 작은 무늬가 약해 매끈함. 단일 프랙탈(fbm)은 어느 크기에서나 같은 β |
| 웅덩이 점 [개/km²] | 여덟 이웃보다 모두 낮아 물이 갇히는 칸의 밀도(가장자리 제외) | 진짜 지형은 거의 0. B-PCG·stream_power는 구조상 0에 가까움 |
| 웅덩이 넓이 [%], 평균 깊이 [m] | 갇힌 물을 넘칠 때까지 채우면 1 cm 넘게 잠기는 땅의 비율, 채운 물의 평균 깊이 | 바다로 물이 못 빠지는 땅이 얼마나 되는지 |
| 하천 밀도 [km/km²] | 상류 면적 0.5 km²(여의도의 약 6분의 1) 이상인 물길의 길이 합 ÷ 넓이 | 0.7이면 1 km² 안에 물길이 700 m. 문턱을 바꾸면 값도 바뀜 |
| 오목도 θ, 경사-면적 R² | 강이 하류로 갈수록 완만해지는 정도와, 그 규칙에 맞는 정도 | θ는 지구에서 보통 0.3~0.7. B-PCG(0.45)·stream_power(0.5)는 입력으로 정한 값이 그대로 나와 지구다움의 근거가 아님(forced) |
| Hack 지수 | 본류 길이 ∝ 유역 넓이^h 의 h | 지구는 약 0.5~0.6. 무작위 물길망에서도 비슷하게 나올 수 있음 |

모든 정의는 `src/Bpcg/Compare/CompareMetrics.cs` 에 있습니다. 어느 지표가 노이즈 지형과 진짜 지형을 가르는지는 아직 따로 확인해야 합니다. 이 도구가 그 확인을 위한 것입니다.

## 한계

- **평면 한 장.** 비교는 12.8 km 평면 한 장의 높이입니다. 행성 전체, 면 경계, 땅속의 일관성은 이 도구로 견주지 않습니다.
- **B-PCG 쪽 조건.** 융기와 출구를 고정한 평면 히어로라, 시드는 칸 흔들기와 지질 노이즈만 바꿉니다. 노이즈 방법보다 시드 사이 차이가 작은 것은 이 때문입니다.
- **예제 지형.** `quilting` 의 가봉 로페 예제는 레이더로 잰 표면 높이라 숲 지붕까지 들어 있고, 기복이 약 540 m입니다. 다른 .npz 파일(키 `z`, `dx`)을 `exemplar` 에 줄 수 있습니다.
- **기존 방법의 구현.** 논문 식과 널리 쓰는 구현 꼴을 따라 이 저장소에서 다시 짰습니다. 원 저자의 구현이 아니라 매개변수에 따라 결과가 달라질 수 있습니다. 매개변수는 모두 설정에서 바꿀 수 있습니다.
- **시간.** 이 노트북의 C# CPU 구현(병렬) 시간입니다. 논문의 GPU 구현 시간과 바로 견주지 않습니다.
- **다시 만들기.** 코드 판이 어셈블리 전체의 ID라, 비교와 상관없는 라이브러리 수정에도 다시 만듭니다.
