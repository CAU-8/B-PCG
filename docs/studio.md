# B-PCG 스튜디오

> 매개변수 하나를 바꿨을 때 산과 강이 어떻게 달라지는지 보려면, 명령을 치고 결과 파일을 열고 그림을 그리는 일을 매번 되풀이해야 합니다. 스튜디오는 이 일을 브라우저 한 화면에서 합니다. 왼쪽에서 값을 바꿔 행성을 만들고, 오른쪽에서 지도와 점수표를 보고, 단추 하나로 Godot에서 걸어 봅니다. 계산은 C# 명령줄이 하므로 .NET 10 SDK가 있어야 합니다.

## 직접 돌려 보기

```bash
uv run bpcg studio
```

1. 터미널에 `[스튜디오] http://127.0.0.1:8765/ 에서 듣습니다 (끄려면 Ctrl+C)` 가 나오고 브라우저가 열립니다.
2. 왼쪽 위 '프로필'을 `tiny`로 두고 '실행'을 누릅니다.
3. '진행' 탭의 막대가 100%가 되고 실행 이름 옆에 '끝'이 붙으면 맞게 돈 것입니다. 걸리는 시간은 몇 초입니다(맥북 에어 M3에서 '지난 시간 2.3 s').
4. '히어로 지도' 탭을 누르면 강 유역 하나의 높이 지도(필드 '지표 고도 [m]')가 바로 보입니다.

끄려면 터미널에서 Ctrl+C를 누릅니다. 모양을 제대로 보려면 `laptop` 프로필로 돌립니다(약 2분).

| 이렇게 켜기 | 언제 |
|---|---|
| `uv run bpcg studio --port 8800` | 8765 포트를 다른 프로그램이 쓰고 있을 때 |
| `uv run bpcg studio --no-browser` | 브라우저를 직접 열고 싶을 때 |

## 화면 둘러보기

### 위 막대

| 부분 | 하는 일 |
|---|---|
| 볼 결과 | 볼 실행을 고릅니다. 스튜디오에서 돌린 실행(`out/studio/`)과 명령줄로 만든 실행(`out/<이름>/`)이 함께 나옵니다. 명령줄로 만든 실행은 보기만 합니다 |
| 방법 비교 | 기존 지형 생성 방법과 B-PCG를 같은 시드로 견주는 화면을 엽니다. [compare.md](compare.md) |
| Godot로 보기 | 고른 실행의 회랑(걸어 다닐 6 km 띠)을 Godot로 복사하고, Godot 창을 띄워 걸어 봅니다 |
| 편집기로 열기 | 같은 복사 뒤 Godot 편집기를 엽니다 |
| 상태 글 | Godot를 찾았는지, 지금 Godot에 어느 실행이 들어 있는지 보여 줍니다 |

### 왼쪽: 실행 설정

- **행성·프로필·시드.** 행성 설정 파일, 크기 묶음(tiny·laptop·lab), 출발 번호입니다. 프로필 옆에 걸리는 시간이 적혀 있습니다.
- **평면 히어로만.** 행성을 만들지 않고, 정해 둔 융기와 출구로 강 유역 하나만 바로 만듭니다. 빠르지만 행성 지도가 없습니다.
- **영역·해상도.** 강 유역(히어로 유역)의 한 변 길이와 칸 간격, 회랑의 길이·폭·간격입니다. 옆에 칸 수와 계산량이 바로 나옵니다.
    - 노트북 기본은 한 변 1280칸, 모두 164만 칸입니다(FHD 화면 화소의 약 80%).
    - 칸이 약 400만 개를 넘거나 회랑이 유역보다 크면 노란 경고가 뜹니다.
    - 한 변이 칸 간격의 3배보다 짧거나 한 변이 5,000칸을 넘으면 실행을 막습니다. 행성을 다 만든 뒤에야 유역에서 멈추는 일을 막으려고 실행 전에 검사합니다.
- **매개변수 목록.** 설정 파일의 값이 절마다 묶여 나옵니다.
    - 값마다 이름, 분류 배지, 설명, 단위, 기본값이 붙습니다.
    - 기본값과 다르게 바꾸면 '바뀜' 배지와 되돌리기 단추(↺)가 나옵니다.
    - 바꾼 값은 브라우저에 남아, 새로 고쳐도 그대로입니다.

분류 배지는 그 값을 바꿀 때 얼마나 조심할지 알려 줍니다.

| 분류 | 뜻 | 예 |
|---|---|---|
| 학습 예정 | 진짜 지형 자료로 맞출 값. 맞춘 값이 생기면 `configs/learned/` 가 덮어씁니다 | `landscape.theta`(강이 하류로 완만해지는 정도), `s_crit_default`(산비탈이 버티는 최대 경사) |
| 손 보정(임시) | 첫 실행에서 생긴 문제(높이가 끝없이 오름, 강이 격자 줄을 따름, 물길이 계속 뒤집힘)를 고치려 손으로 바꾼 값. 바꾼 기록이 같이 나옵니다 | `slope_exponent_n`, `jitter`, `elevation_limit_*`, `deposition_g_l0` |
| 물리 상수 | 지구에서 잰 값 | `planet.radius_m`(반지름), 암석 밀도, 바닷물의 양 |
| 해상도·성능 | 칸 크기와 걸리는 시간을 정하는 프로필 값 | `profile.grid.*`, `profile.hero.*` |
| 보기용 디테일 | 굽기 때 회랑 지표에만 더하는 잔무늬. 솔버 결과와 점수표는 바꾸지 않습니다 | `detail.*` |
| 문헌 기본값 | 논문과 관측 범위에서 고른 나머지 값 | 대부분 |

### 탭

| 탭 | 보여 주는 것 |
|---|---|
| 진행 | 전체 진행 막대, 지금 단계, 지난 시간과 남은 시간, 단계 목록, 실행 기록의 마지막 줄들. 문제가 생기면 위에 노란 경고가 뜹니다(아래 '막혔을 때') |
| 개요 | 프로필·시드·바다 비율·유역 위치, 기본값에서 바꾼 설정, 솔버가 멈추기까지의 반복 그래프, 단계별 시간, 점수표 |
| 행성 지도 | 행성 전체를 세계 지도처럼 편 그림(1024 × 512 픽셀) |
| 히어로 지도 | 강 유역 하나의 지도. 빨간 사각형이 Godot로 구운 회랑입니다 |
| 그림 | 결과 그림. 그림 스크립트를 아직 C# 결과에 맞추지 않아 새 실행에는 그림이 없습니다 |
| 매개변수 설명 | 모든 매개변수의 표(분류, 설명, 단위, 기본값, 바꾼 값, 고른 실행의 값, 파일) |

지도 탭 쓰는 법:

- **필드 고르기.** 필드는 지형, 판·지각, 해양, 기후, 물, 지질·암석, 동굴, 흙으로 묶여 있습니다. 바다 수심, 지하수면 깊이처럼 읽기 쉽게 계산한 지도도 있습니다.
- **읽는 법.** 지도 위 설명 상자에 이름, 단위, 뜻, **어떻게 읽나**, 값 범위가 나옵니다. 처음 보는 지도는 여기부터 읽습니다.
- **색.** 색표, 색 범위, 로그 눈금, 음영(기복 그림자)을 바꿀 수 있습니다. 처음 색 범위는 값의 아래 2%~위 2%를 뺀 범위입니다.
- **겹쳐 그리기.** 행성 지도에는 해안선·판 경계·유역 위치, 히어로 지도에는 강·호수·선상지·동굴 입구·회랑을 겹칩니다.
- **칸 하나 보기.** 마우스를 올리면 값과 위치가, 누르면 오른쪽에 그 칸의 모든 필드 값과 땅속 층 기둥(깎여 없어진 층, 지표에 드러난 층, 기반암)이 나옵니다. 칸 정보의 줄을 누르면 그 필드를 지도에 그립니다.
- **움직이기.** 휠로 확대하고, 끌어서 옮깁니다.

## 값 하나를 바꾸면 Godot까지 어떻게 가나

1. 왼쪽에서 값을 바꾸고 '실행'을 누르면, 서버가 먼저 키 이름과 값의 형식을 검사합니다. 없는 키는 비슷한 키를 알려 주며 막습니다.
2. 서버가 C# 명령줄을 빌드하고(바뀐 것이 없으면 몇 초), `bpcg all … --set 키=값` 과 같은 실행을 돌립니다.
3. 실행이 찍는 기록 줄(`[1단계] …`, `[2단계] 솔버 끝 …`)을 한 줄씩 읽어 진행 막대로 바꿉니다. 같은 프로필의 지난 실행이 있으면 그때 잰 시간으로 남은 시간을 셉니다.
4. 실행 폴더(`out/studio/<실행 id>/`)에 설정과 기록이 남습니다. 서버를 다시 켜도 목록과 기록이 그대로 보입니다.
5. 'Godot로 보기'를 누르면, 회랑 파일을 `engine/baked/` 로 복사하고 엔진을 빌드한 뒤 Godot를 띄웁니다.

명령줄에서 같은 일을 하려면:

```bash
uv run bpcg all --profile laptop --out out/theta05 --set landscape.theta=0.5 --set fans.enabled=false
uv run bpcg bake --hero out/theta05/hero --engine
```

`--set 키=값` 은 여러 번 쓸 수 있습니다.

- 값은 TOML 문법입니다: 실수 `0.5`, 참·거짓 `true`, 목록 `[0.02, 0.07]`, 글자 `"…"`.
- 프로필 값은 앞에 `profile.` 을 붙입니다. 예: `--set profile.hero.size_m=40000.0`.
- 행성 이름과 프로필 이름은 `--set` 대신 `--planet`, `--profile` 로 고릅니다.
- `hero --from` 은 행성 묶음의 설정을 그대로 쓰므로 `--set` 을 받지 않습니다.

<details><summary>실행이 도는 자세한 순서 (서버 안쪽)</summary>

1. **검사.** `bpcg_studio.config.checked_overrides` 가 키와 형식을, `jobs.domain_errors` 가 유역·회랑 크기를 봅니다. 실수 자리의 `nan`·`inf` 도 막습니다(묶음 목록 파일에 null 로 적혀 다음 단계가 깨지기 때문). 이미 도는 실행이 있으면 409로 막습니다. 검사와 등록을 한 잠금 안에서 해서, 거의 같은 때 누른 두 요청도 하나만 시작합니다.
2. **실행.** `dotnet build src/Bpcg.Cli -c Release` 뒤 `dotnet src/Bpcg.Cli/bin/Release/net10.0/Bpcg.Cli.dll all --profile … --seed … --out out/studio/<실행 id> --set …` 를 하위 프로세스로 돌립니다.
3. **진행률.** `bpcg_studio/progress.py` 의 `STAGES` 표가 기록 줄을 단계로 바꿉니다. 솔버는 `솔버 반복 k` 줄로 단계 안 진행을 셉니다. 유역 칸 수, L0 칸 수, 회랑 표본 수(`jobs.cost_of`)가 지난 실행과 다르면 그 비율로 단계 시간을 늘이거나 줄입니다.
4. **그림 단계.** 행성이 있으면 `analysis/figures/render_results.py` 로 그림을 그리는 단계가 있습니다. 이 스크립트가 아직 C# 결과를 읽지 못해 지금은 '건너뜀'으로 적습니다(`jobs.FIGURES_READY`).
5. **기록 파일.** `job.json`(프로필·시드·바꾼 값·상태·단계별 시간·서버 pid)과 `job.log`(기록 전체)를 씁니다. 서버가 꺼질 때 돌던 실행은 '멈춤', 그때 돌던 단계는 '실패(서버 꺼짐)'로 적힙니다. 윈도우에서 다른 프로그램이 `job.json` 을 열고 있어 쓰지 못해도 실행은 멈추지 않고 다음에 다시 씁니다.
6. **Godot로 보기.**
    1. Godot 4.7.2 .NET 판을 찾습니다(`GODOT_NET` 환경 변수 → `.tools/godot-net/` → `GODOT` 환경 변수). 버전이 `4.7.2.stable.mono` 인지 화면 없이 확인합니다.
    2. `corridor/manifest.json` 이 적은 파일을 `engine/baked/` 로 복사하고, 이전 회랑에만 있던 파일은 지웁니다. 어느 실행인지 `engine/baked/studio_run.json` 에 적습니다.
    3. `dotnet build engine/Bpcg.Engine.csproj` 로 엔진을 빌드합니다.
    4. `Godot --headless --path engine --import` 를 **임시 HOME** 으로 돌려 새 파일을 가져옵니다.
    5. `Godot --path engine res://scenes/main.tscn`(처음 화면을 건너뛰고 회랑) 또는 `-e`(편집기)를 띄웁니다.

</details>

| 보이는 것 | 까닭 | 고치는 법 |

| '실행'이 409로 막힘 | 다른 실행이 돌고 있음(같은 `out/` 을 보는 다른 스튜디오의 실행 포함) | 끝날 때까지 기다리거나 진행 탭에서 멈춥니다 |
| 그림 탭이 비어 있음 | 그림 스크립트가 아직 C# 결과를 읽지 못함 | 지금은 정상입니다. 지도 탭으로 봅니다 |
| 'Godot로 보기'가 Godot를 못 찾음 | Godot .NET 판을 받지 않음 | `./scripts/setup.sh --godot` 로 받습니다 |

## 알아 둘 것

- **시간.** `laptop` 은 실행 하나에 약 2분, `lab` 은 훨씬 오래 걸립니다. 한 번에 한 실행만 돕니다. 유역을 키우면 시간이 칸 수에 거의 비례해 늘어납니다.
- **임시 값.** '손 보정(임시)'과 '학습 예정' 값은 자료로 맞추기 전의 값입니다. 스튜디오로 찾은 좋은 값은 근거와 함께 PR로 `configs/` 에 넣습니다.
- **지도는 다시 표본한 그림입니다.** 행성 지도의 픽셀은 가장 가까운 칸의 값이라 극 근처는 옆으로 늘어나 보입니다. 큰 유역의 히어로 지도는 칸 여러 개를 한 픽셀로 묶은 값입니다(연속값은 평균, 범주는 가운데 칸, 강은 하나라도 있으면 있음). 정확한 값은 칸을 눌러 봅니다.
- **Godot 설정은 건드리지 않습니다.** 화면 없이 도는 단계(버전 확인, 가져오기)는 모두 임시 HOME으로 돌립니다. 마지막에 창을 띄울 때만 내 설정을 씁니다.
- **다른 실행은 읽기만.** `out/` 의 다른 실행은 보기만 하고 고치지 않습니다. 캐시는 `out/studio/.cache/` 에만 쓰고, 지워도 다시 만듭니다.

<details><summary>보안: 다른 웹 페이지가 실행을 시작하지 못하게 막는 것들</summary>

- 서버는 내 컴퓨터(127.0.0.1)에서만 듣고, Host 머리글이 127.0.0.1·localhost가 아니면 막습니다.
- POST는 JSON만 받습니다. 다른 사이트에서 온 요청(Origin, Sec-Fetch-Site)과 본문 길이가 이상한 요청을 막습니다.
- 모든 응답에 iframe 금지 머리글(`X-Frame-Options: DENY`, `frame-ancestors 'none'`)을 붙여, 다른 페이지가 '실행'·'Godot로 보기'를 몰래 누르게 하지 못합니다.
- 그림·회랑·필드 파일 이름은 경로가 없는 이름만 받습니다(`bpcg_studio/names.py`, 윈도우의 `D:x` 같은 드라이브 상대 경로 포함).
- 인터넷 자원(CDN, 글꼴)을 쓰지 않아 인터넷 없이도 돕니다.

</details>
