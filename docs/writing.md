# 글쓰기 안내서: 고치기 전·후 예시와 틀

> 이 저장소의 문서와 화면 글은 처음 합류한 팀원이 혼자 읽을 수 있어야 합니다. 규칙은 [CLAUDE.md](../CLAUDE.md) 2~5장에 있고, 이 안내서는 그 규칙을 실제 문장에 적용한 예를 모읍니다. 글을 쓰기 전에 1장의 예를 한 번 훑고, 저장하기 전에 6장의 점검표를 봅니다.

---

## 1. 고치기 전·후: 문서

예마다 무엇을 고쳤는지 한 줄로 붙였습니다. 고친 글은 모두 같은 세기입니다: 왜 필요한지 → 보이는 현상과 이름 → 독자가 품을 질문과 답 → 작은 숫자 예 → 식.

### 1.1 정상상태

```text
(전) 수천만 년을 시간 순서로 돌리지 않습니다. '솟는 속도 = 깎이는 속도'인 다 자란 지형을 고정점 반복으로 바로 풉니다.
```

```text
(후) 실제 산은 수백만 년에서 수천만 년에 걸쳐 자랍니다. 이것을 1년씩 계산하면 행성 하나에 몇 시간이 걸립니다.
    그런데 오래 자란 산은 어느 때부터 모양이 거의 바뀌지 않습니다. 땅이 솟는 만큼 강이 깎아 내기 때문입니다.
    그럼 처음부터 그 '다 자란 모양'만 바로 구할 수는 없을까요? 있습니다.
    바다에서 출발해 상류로 한 칸씩 올라가며, 솟는 속도와 깎이는 속도가 같아지는 높이를 쌓습니다.
    이렇게 더 바뀌지 않는 상태를 정상상태라고 부릅니다.
    예를 들어 땅이 1년에 1 mm 솟는 곳이면, 그 칸의 강은 1년에 정확히 1 mm 를 깎는 경사가 됩니다.
```

고친 점: '고정점 반복'을 빼고, 왜 시간 순서로 돌리지 않는지(몇 시간이 걸림)와 숫자 예(1 mm)를 넣었습니다.

### 1.2 노드 흔들기와 격자 정렬 지수

```text
(전) jitter = 1.0   # 노드 흔들기 세기 (칸 크기 대비). 0.4 는 격자 정렬 지수 1.70, 1.0 은 1.12~1.2
```

```text
(후) 지도는 바둑판 같은 칸으로 되어 있습니다. 칸 중심이 줄을 맞춰 서 있으면 문제가 하나 생깁니다.
    물은 이웃 여덟 칸 가운데 하나로만 흐르므로, 강이 가로·세로·45° 방향으로만 곧게 뻗습니다.
    그래서 칸 중심을 제자리에서 조금씩 흔들어 놓습니다(노드 흔들기).
    세기 1.0 이면 칸 중심이 위아래·좌우로 최대 반 칸씩 옮겨집니다. 세기 0.4 면 최대 0.2 칸입니다.
    잘 흔들렸는지는 이렇게 잽니다. 강 칸마다 여섯 칸 아래쪽까지의 방향이 격자 방향에 얼마나 가까운지 셉니다.
    그 비율을, 강이 아무 방향으로나 흐를 때의 비율로 나눕니다(격자 정렬 지수).
    1 이면 격자를 전혀 편들지 않는 것이고, 클수록 강이 격자 줄을 따릅니다. 합격선은 1.3 미만입니다.
    세기 0.4 에서는 1.70(격자 방향이 아무렇게나 흐를 때보다 1.7배 많음), 1.0 에서는 1.12~1.2 였습니다.
```

고친 점: 왜 흔드는지(강이 곧게 뻗음)를 먼저 쓰고, 지수의 뜻과 1의 의미, 합격선을 넣었습니다.

### 1.3 생략된 이유 채우기

```text
(전) deposition_g_l0 = 0.0   # L0 (칸 19.5 km) 에서는 퇴적 항이 물길을 진동시켜 끔
```

```text
(후) deposition_g_l0 = 0.0   # 강이 실어 온 흙을 내려놓는 정도(퇴적)를 행성 전체 지도(칸 19.5 km)에서는 끔.
                             # 켜면 물이 나르는 흙의 양이 물길 방향을 따라 바뀌고, 그 변화가 다시 물길을 바꿈.
                             # 시험에서 반복 200번 안에 끝나지 않았고, 열 칸 가운데 약 세 칸(26%)의 방향을 묶어야 했음.
                             # 히어로 유역(칸 25 m)에서는 deposition_g = 1.0 으로 켬
```

고친 점: '퇴적 항', '진동'을 현상으로 풀고, 켜면 무슨 일이 생기는지와 다른 곳의 값을 함께 적었습니다.

### 1.4 줄임말 흐름도

```text
(전) 2단계 솔버 (L0, 면당 l0_n, 노드 흔들기)
     [채움 → D8(히스테리시스) → Q, Qs → 경사 법칙 → 층별 적분] 을 방향이 안 바뀔 때까지
```

```text
(후) 2단계: 산과 강의 모양 풀기 (행성 전체 지도 L0)
     ① 물이 갇히는 웅덩이를 메움          ② 칸마다 물이 흘러갈 이웃을 고름 (D8)
     ③ 위에서부터 물과 흙의 양을 더함 (Q, Qs) ④ 물의 양으로 강과 산비탈의 경사를 정함
     ⑤ 바다에서부터 경사를 쌓아 높이를 만듦
     ⑤에서 높이가 바뀌면 ②의 물길도 바뀝니다. 그래서 물길이 더 바뀌지 않을 때까지 ①~⑤를 되풀이합니다.
```

고친 점: 기호만 있던 상자를 단계마다 동사로 풀고, 왜 되풀이하는지 한 줄을 붙였습니다.

## 2. 문서 틀

### 2.1 입구 문서 (README, studio, compare, engine README 등)

````markdown
# <무엇에 대한 문서인지 평범한 말로>

> <요약 2~4문장. 이것이 무엇인지, 왜 필요한지, 결론을 바꾸는 조건. 용어·기호·식 없이.>

## 직접 돌려 보기

```bash
<그대로 복사해서 돌리는 명령>
```

- 맞게 돌았으면: <화면에 보일 글이나 생길 파일>
- 걸리는 시간: <잰 값> (<프로필>, <잰 기계>)

## <본문: 하는 일 순서대로>

## 막혔을 때
| 보이는 것 | 까닭 | 고치는 법 |
|---|---|---|

## 더 볼 곳
- <이어 읽을 문서와 코드 위치>
````

### 2.2 개념 하나를 설명하는 절

```markdown
### <개념의 쉬운 이름> (<프로젝트 용어>)

<왜 필요한지 1~2문장. 이것이 없으면 무엇이 곤란한지.>
<보이는 현상 1~2문장, 끝에 이름을 괄호로.>
<독자가 품을 질문을 문장으로 던지고 바로 답.>
<작은 숫자로 한 번 넣어 본 예.>

<식이 필요하면: 식이 말하는 바 한 문장 → 식 → 기호마다 뜻과 단위.>

<details><summary>근거와 유도</summary>
<출처, 유도 과정, 버린 안. 이미 아는 사람이 건너뛰는 부분.>
</details>
```

## 3. 화면 글 예시

### 3.1 버튼·상태·오류

| 종류 | 고치기 전 | 고친 뒤 |
|---|---|---|
| 버튼 | `실행` | `행성 만들기` |
| 버튼 | `Godot로 보기` | `Godot로 걸어 보기` |
| 상태 | `running` | `히어로 유역 만드는 중 (3/5단계)` |
| 오류 | `size_m too small` | `히어로 한 변(size_m 900 m)이 칸 간격(spacing_m 500 m)의 3배보다 작습니다. size_m 을 1,500 m 이상으로 늘리세요.` |

오류 글은 무엇이 틀렸는지, 받은 값, 고치는 법을 모두 씁니다.

### 3.2 지도 이름표와 읽는 법

```text
(전) 이름: 경사   읽는 법: 물을 보내는 이웃 칸까지의 경사(높이 차 / 거리)입니다.
(후) 이름: 경사 (물이 흘러가는 쪽)
    읽는 법: 밝을수록 가파릅니다. 0.1 은 10 m 갈 때 1 m 내려가는 비탈(약 6°)이고, 1.0 은 45° 입니다.
            산맥이 밝고, 강 바닥과 평야가 어둡습니다.
```

### 3.3 매개변수 도움말

```text
(전) s_crit_default = 0.6   # 암석 정보가 없을 때의 임계 경사 [m/m]
(후) s_crit_default = 0.6   # 산비탈이 무너지지 않고 버티는 가장 가파른 경사(임계 경사), 암석 정보가 없을 때 씀.
                            # 0.6 은 10 m 갈 때 6 m 오르는 비탈, 약 31°. 키우면 산이 뾰족하고 높아짐
```

| 고치기 전 | 고친 뒤 | 고친 점 |

## 6. 저장 전 점검표

- [ ] 요약이 2~4문장이고, 용어·기호·식 없이 무엇인지와 왜 필요한지를 말합니다.
- [ ] 처음 나온 용어는 모두 현상을 보인 뒤에 이름을 붙였습니다. 괄호 안 용어는 하나씩입니다.
- [ ] 개념마다 왜 필요한지, 독자의 질문과 답, 작은 숫자 예가 있습니다.
- [ ] 식을 지우지 않았고, 식마다 앞에 뜻 한 문장, 뒤에 기호의 뜻과 단위가 있습니다.
- [ ] 숫자에 단위가 있고, 큰 숫자의 비유는 5장 표에서 가져왔습니다.
- [ ] 한 문장에 정보 하나, 문단은 2~3줄입니다. 피동형·번역투([CLAUDE.md](../CLAUDE.md) 2.3 표)가 없습니다.
- [ ] 요약과 본문에 같은 말을 바꿔 쓴 문장이 없습니다.
- [ ] 작업 과정과 예고("살펴보겠습니다")가 없습니다.
- [ ] 결론을 바꾸는 조건이 빠지지 않았고, forced·emergent 지표를 구분했습니다.
- [ ] 입구 문서라면 '직접 돌려 보기'의 명령을 실제로 돌려 확인했습니다.
- [ ] 새 용어를 [glossary.md](glossary.md)에 넣었습니다.
