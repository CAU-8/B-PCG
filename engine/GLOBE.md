# 지구본 장면 (scenes/globe.tscn)

The globe scene shows the whole generated planet as a rotatable globe. The C# baker (`src/Bpcg/Bake/Globe.cs`) resamples the L0 planet onto a 6 × N × N cube-sphere grid and writes `<baked dir>/globe/`; Godot raises the sphere by elevation (exaggerated ×20 by default), paints it with one chosen layer (elevation, plates, climate, water, rock, caves, …), and overlays rivers, lakes and a 15° lat/lon grid. Every layer carries its own title, unit, legend and Korean explanation from `globe.json`.

> 회랑은 행성의 6 km 띠 하나만 보여 줍니다. 그 띠가 행성 어디에 있고, 판과 산맥과 강이 행성 전체에서 어떻게 놓였는지는 지구본 장면에서 봅니다. 지구본을 돌리고, 레이어(고도, 판, 기온 등)를 바꿔 칠하고, 마우스를 올리면 그 자리의 위도·경도와 값이 나옵니다. 지구본 장면은 계산하지 않습니다. 굽기(`Bpcg` 의 `Globe.BakeGlobe`)가 미리 써 둔 값을 칠하기만 합니다.

## 직접 돌려 보기

```bash
uv run bpcg all --profile tiny --out out/tiny          # out/tiny/{planet,hero,corridor,globe}
G=.tools/godot-net/Godot_mono.app/Contents/MacOS/Godot
dotnet build engine/Bpcg.Engine.csproj
$G --path engine res://scenes/globe.tscn -- --baked-dir="$PWD/out/tiny/corridor"   # 지구본만 열기
```

- 맞게 열렸으면: 행성 지구본이 뜨고, 오른쪽 위 패널에 레이어 단추가, 지구본 위에 주황 핀 '히어로 유역 (위도, 경도)'이 보입니다.
- 편집기에서는 `scenes/globe.tscn` 을 열고 '현재 장면 실행'(F6, 맥은 Cmd+R)을 누릅니다.
- 처음 화면의 '지난 결과'에서 실행을 골라 지구본을 열 수도 있습니다.
- 지구본에서 M을 누르면 회랑으로, N을 누르면 처음 화면으로 갑니다.

`--baked-dir` 을 빼면 처음 화면이 고른 실행, 그다음 `res://baked` 의 지구본을 읽습니다. 굽기 폴더 안의 `globe/` 를 먼저 찾고, 없으면 옆의 `../globe` 를 찾습니다.

자료가 없으면(`globe.json` 이 없음) 화면 가운데에 '지구본 자료가 없습니다'와 굽는 명령이 나옵니다. 자료가 있는데 크기·형식이 틀리면 '지구본 자료를 읽지 못했습니다'와 그 까닭이 나옵니다. 어느 쪽이든 장면은 멈추지 않습니다.

|---|---|
| 왼쪽 위 | 지금 레이어, 고도 과장, 자동 회전, 카메라의 해수면 위 높이(km). 마우스가 가리키는 자리의 위도·경도(북위·남위, 동경·서경), 고도, 고른 레이어 값(단위 포함, 값이 없으면 '값 없음 · 이유'), 그 칸의 강 등급·호수. 강 등급이 지금 문턱 아래라 그리지 않는 칸이면 '(지금은 4 등급부터 그리므로 그리지 않음)' 을 붙입니다 |
| 왼쪽 위 상자 | 클릭으로 고정한 칸: 위도·경도, 칸 번호(면·행·열), 무리별 모든 레이어 값, 강·호수 |
| 오른쪽 위 패널 | 지구본 설명(globe.json 의 description, 시드, 칸 크기), 무리별 레이어 버튼, 겹쳐 보기(강·호수 설명과 등급 색, 경위선), 그늘·대기 빛(꾸밈이고 자료가 아니라는 설명과 함께), 고도 과장, 히어로로 날아가기, 회랑으로 들어가기. 버튼에 마우스를 올리면 그 레이어 설명이 뜹니다 |
| 오른쪽 아래 범례 | 레이어 이름과 단위(로그·범주 표시), 색 막대와 최소·가운데·최대 값 또는 범주 색 목록(넓이 몫 %)과 그 몫의 잣대(육지 기준인지 행성 전체 기준인지), '무엇인가'(레이어 설명)와 '읽는 법'(색 읽는 법) |
| 지구본 위 | 주황 핀과 이름표 '히어로 유역 (위도, 경도)': 자세히 만든 히어로 영역의 가운데. 동굴처럼 드문 범주 레이어는 그 칸마다 같은 색 점(화면 크기 일정)을 덧찍습니다. 지구본 둘레의 푸른 빛은 지구본 바깥에만 그리는 꾸밈이고 자료가 아닙니다 |

범례 읽는 법:

- 막대 가운데 글은 범위가 0을 걸치면 0입니다(고도의 해수면, 기온의 0 °C, 솟음과 가라앉음의 경계). 막대 위 흰 선이 그 자리입니다. 그 밖에는 양 끝의 가운데 값입니다.
- 자료가 막대 범위 밖까지 있으면 끝 글에 '이하'·'이상'을 붙입니다. 그 칸은 끝 색으로 칠합니다.
- 범주가 12개보다 많으면(판 등) 색 목록을 스크롤 상자에 넣습니다.

## 레이어

레이어 목록, 이름, 단위, 색표, 설명은 모두 `globe.json` 에서 옵니다. 엔진은 이름을 하나도 외우지 않고(고도 `elevation` 만 마우스 자리에 늘 보여 줌), 파일에 있는 대로 패널을 만듭니다. 지금 굽기 코드가 쓰는 레이어는 다음과 같습니다. '사슬' 칸은 이 값이 세 원인-결과 사슬 가운데 어디에 드는지입니다: 뼈대(판 → 지각 → 해양저·융기), 조각(암석 + 비 → 골짜기), 내부(물 높이 → 지하수 → 동굴).

| 키 | 레이어 (무리) | 단위 | 사슬 | 보이는 것 |
|---|---|---|---|---|
| 1 | 고도 (지형) | m | 조각의 결과 | 바다는 깊을수록 진한 파랑, 0 m 에서 색이 끊기고 육지는 초록 → 갈색 → 흰색 |
| 2 | 칸 안 기복 (지형) | m | 조각 | 격자에 안 보이는 골짜기 바닥 ~ 능선 높이 차. 바다는 값 없음 |
| 3 | 판 (판·지각) | 범주 | 뼈대 | 판마다 다른 색 (색의 순서에는 뜻 없음) |
| 4 | 판 경계 (판·지각) | 범주 | 뼈대 | 수렴(빨강), 발산(파랑), 변환(노랑) |
| 5 | 지각 종류 (판·지각) | 범주 | 뼈대 | 해양 지각(청회색), 대륙 지각(황갈색) |
| 6 | 융기 속도 (판·지각) | mm/yr | 뼈대 | 흰색 ≈ 0, 주황·갈색은 솟음, 보라는 가라앉음 |
| 7 | 해양저 나이 (해양) | Myr | 뼈대 | 빨강 = 젊은 해령 근처, 파랑 = 오래됨. 대륙은 값 없음 |
| 8 | 연평균 기온 (기후) | °C | 조각의 입력 | 흰색 = 0 °C, 파랑은 춥고 빨강은 더움 |
| 9 | 연강수량 (기후) | m/yr | 조각의 입력 | 옅은 노랑 = 메마름, 짙은 남색 = 비가 많음 |
| — | 강 유량 (물) | m³/s, 로그 눈금 | 조각 | 저장 값은 log10(m³/s). 마우스 자리·범례는 10^값 m³/s 로 보여 줍니다 |
| — | 지표 암석 (지질) | 범주 | 조각의 입력 | 회랑 장면의 지층 단면과 같은 암석 색. 바다는 '바다 (지질 계산 안 함)' 회색, 넓이 몫은 육지 기준 |
| — | 지질 틀 (지질) | 범주 | 뼈대 | 탄산염 탁상지, 습곡충상대, 기반암 + 화산호. 바다는 회색, 넓이 몫은 육지 기준 |
| — | 동굴 (동굴) | 범주 | 내부 | 아래층(청록), 위층(주황), 두 층 모두(자주). 드물어서 칸마다 점도 찍음. 설명에 L0 칸 수와 지구본 칸 수 |

지하수면 깊이와 골짜기 깊이는 싣지 않습니다. 왜 그럴까요? 행성 지도(L0)에서는 지하수면이 골짜기 바닥에 거의 붙어 있습니다(laptop 육지 칸에서 둘의 차 가운데값 0.15 m). 그래서 지하수면 깊이는 '칸 안 기복의 절반'(mean_fraction 0.5)과 같고, 골짜기 깊이도 칸 안 기복과 거의 같습니다(가운데값 비 1.00). 따로 칠하면 물에 대한 지도처럼 보이지만 실제로는 기복 지도입니다. 그래서 칸 안 기복의 설명에 이 관계를 적어 둡니다.

바다 칸의 지표 암석과 지질 틀은 생성기가 계산하지 않고, 빈자리를 채우는 값(화강암, 탄산염 탁상지)만 둡니다. 그래서 지구본에서는 '값 없음' 범주(번호 255, 회색)로 칠하고, 넓이 몫은 육지만 셉니다.

## 그리는 방법

엔진 담당자가 지구본 그리기를 고칠 때 읽는 부분입니다.

<details><summary>좌표, 격자, 메시, 셰이더</summary>

**좌표.** Godot 좌표 = (행성 x, 행성 z, −행성 y) 입니다. 행성 자전축 z(북쪽)가 Godot +Y 이고, 이 바꿈은 회전(행렬식 +1)이라 면 기저의 오른손 규칙 u × v = n 이 그대로입니다. 위도 = asin(y), 경도 = atan2(−z, x) (Godot 좌표, 도). 지구본 반지름 1 이 해수면 반지름 `radius_m` 입니다. 설정의 자전축(`planet.axis`)이 z 가 아니면 굽기가 먼저 자전축을 z 로, 경도 0 의 기준(히어로 찾기와 같은 규칙)을 x 로 돌린 뒤 같은 바꿈을 합니다(`frame.axis_rotation`). 그래서 자전축은 늘 Godot +Y 이고, 엔진이 계산하는 위도·경도가 기후의 위도와 히어로의 위도·경도와 같습니다. 히어로의 `lat_deg`, `lon_deg` 도 늘 이 좌표의 단위 벡터에서 다시 계산합니다.

**격자.** 면 f 의 기저 n, u, v 로 방향 ∝ n + tan(a·π/4)·u + tan(b·π/4)·v (등각 큐브스피어). 칸 (행 r, 열 c) 의 중심은 a = −1 + 2(c + ½)/N, b = −1 + 2(r + ½)/N 이고, 꼭짓점 (r, c) 는 a = −1 + 2c/N, b = −1 + 2r/N 입니다. 거꾸로 방향 → 칸은 n 과의 내적이 가장 큰 면을 고르고 a = atan(d·u / d·n) / (π/4) 로 구합니다(`GlobeData.DirectionToCell`). 행은 v, 열은 u 쪽이라 묶음의 셀 번호 c = f·n² + j·n + i 와 같은 규칙입니다.

**메시** (`GlobeView.cs`). 면마다 꼭짓점 (N+1)² 개의 단위 방향, UV = (열/N, 행/N), 삼각형은 바깥에서 시계 방향(앞면)입니다. 면 경계는 tan(±π/4) 를 정확히 ±1 로 두고 거울 대칭으로 계산해서 이웃 면과 꼭짓점이 비트 단위로 같습니다. 이웃 면이 나누는 꼭짓점의 고도도 굽기가 같은 값으로 쓰므로 틈이 생기지 않습니다. N = 256 이면 꼭짓점이 약 40 만 개입니다.

**셰이더** (`shaders/globe.gdshader`).

- 꼭짓점: 면별 모서리 고도 텍스처(RF, (N+1)²)를 읽어 r = 1 + 과장 × max(고도, 해수면) / `radius_m` 으로 밉니다. 바다는 해수면 높이로 평평하고 색으로만 수심을 보입니다. 과장 ×1 에서는 가장 높은 산도 반지름의 0.1 % 남짓이라 보이지 않습니다.
- 색: 고른 레이어의 RGBA 텍스처(칸 하나 = 텍셀 하나, `GlobeData` 가 처음 고를 때 색표로 만듦). 범주 값은 가장 가까운 텍셀입니다. 연속 값은 셰이더가 이웃 텍셀 넷을 직접 읽어 선형 보간하는데, 텍스처 알파에 적힌 텍셀의 종류(255 = 값, 128 = `color_break` 아래, 0 = 값 없음)가 넷 가운데 하나라도 다르면 가장 가까운 텍셀을 씁니다. 그래서 값 없는 회색이 이웃 칸에 번지거나 해안에서 얕은 바다 파랑과 낮은 땅 초록이 섞이는 등, 범례에 없는 색이 생기지 않습니다(그 경계만 칸 모양으로 각짐).
- 해수면의 끊김: 색표 값은 늘 엄격히 늘어납니다(같은 값의 매듭 없음). 고도 색표는 바다의 마지막 매듭이 −0.5 m(가장 얕은 바다 색), 육지의 첫 매듭이 0 m(낮은 땅 초록)라서 그 사이 0.5 m 에서만 두 색이 섞이고, 고도 필드의 `color_break` = 0 이 위의 '섞지 않음'을 켭니다. 엔진은 같은 값의 매듭이 둘 와도 멈추지 않고 그 값부터 뒤 매듭의 색을 쓰지만, 굽기 코드와 검사는 엄격히 늘어나는 색표만 씁니다.
- 겹쳐 보기: 강 등급과 호수 값을 바이트 그대로 담은 텍스처. 등급별 색과 문턱은 uniform 이라 텍스처를 다시 만들지 않습니다.
- 그늘(기복만): 화면 공간 미분(dFdx, dFdy)으로 구한 면 법선 n_face 와 매끈한 구의 법선 n_sphere 가 카메라 왼쪽 위 앞에서 오는 빛 l 을 받는 정도의 차이만 밝기로 바꿉니다. lit = clamp(1 + 1.5 · (n_face·l − n_sphere·l), 0.6, 1.4). 구의 둥근 모양 자체는 어둡게 하지 않으므로 평평한 곳은 화면 가장자리에서도 lit = 1(범례 색 그대로)이고, 비탈만 밝거나 어둡습니다. 과장을 키우면 기복이 더 드러납니다. G 로 끄면(`shade_relief`) 대기 빛도 함께 꺼지고 모든 칸이 범례 색입니다.
- 드문 범주의 점: `point_markers` 레이어(동굴)를 고르면 0 도 '값 없음' 도 아닌 칸마다 범주 색 점(7 px, 화면 크기 일정)을 칸 모서리 가운데 가장 높은 곳 바로 위에 찍습니다(`GlobeView.PointMarkers`).
- 대기 빛(`shaders/atmosphere.gdshader`): 지구본보다 조금 큰 구에 그리되, 시선이 해수면 구를 지나는 자리는 버립니다. 그래서 빛은 지구본 바깥 테두리에만 있고 지구본 위의 색을 바꾸지 않습니다.
- Godot 조명은 쓰지 않습니다(`unshaded`). 그래서 화면 색 = 범례 색 × 기복 그늘(평평하면 1)입니다.

화면 밖 판정 상자는 가장 큰 과장(×100)의 최고 고도에 맞춰 둡니다. 셰이더가 꼭짓점을 밀어 내기 때문입니다.

</details>

## 파일 형식 요약 (`globe.json`)

자세한 정의는 `src/Bpcg/Bake/Globe.cs` 의 설명 주석에 있습니다. 엔진이 쓰는 키만 적습니다.

| 키 | 뜻 |
|---|---|
| `format`, `format_version` | `"bpcg-globe"`, 1 (엔진은 1 이하만 읽음) |
| `radius_m`, `face_res`, `sea_level_m` | 반지름(m), 면당 칸 수 N, 해수면(0 m) |
| `faces[6]` | `{index, n, u, v}` Godot 좌표의 면 기저 |
| `corners` | `corners_elevation_m.bin`, float32 (6, N+1, N+1), m |
| `fields[]` | `name`, `label`, `group`, `unit`, `file`, `dtype`(float32·uint8), `shape` (6, N, N), `kind`(continuous·categorical), `description`, `how_to_read`. 연속: `min`, `max`(색표 양 끝), `colormap` `[[값, [r, g, b]], …]`(값이 엄격히 늘어남), `log`, `data_min`, `data_max`, `nan_label`, 있으면 `color_break`(이 값의 양쪽 칸끼리 섞지 않음; 고도는 0). 범주: `categories` `[{id, label, rgb, area_fraction, no_data?}]`, `area_fraction_basis`(`land`·`planet`), `area_fraction_note`(범례에 보이는 잣대 글), 있으면 `point_markers`(true 면 0 이 아닌 칸마다 점)와 `n_nonzero_cells`. `rgb` 가 null 이거나 짧으면 엔진은 '값 없음' 색으로 칠합니다 |
| `overlays[]` | `rivers`(유량 등급 0 ~ 4), `lakes`(0, 1). uint8 (6, N, N), `categories` 의 색과 이름 |
| `hero` | `{unit (Godot 좌표), lat_deg, lon_deg, size_m, label, description}` 또는 null |
| `title`, `description`, `seed`, `nan_rgb` | 패널 머리글과 설명, 시드, '값 없음' 색 |
| `frame` | `rule`, `axis_rotation`(자전축을 z 로 돌리는 회전, 자전축이 z 면 단위 행렬), `matrix_planet_to_godot` |

`.bin` 은 머리글 없는 리틀 엔디언 배열을 [면][행][열] 순서로 늘어놓은 것이고, 엔진은 크기가 정확히 6 × N² × (4 또는 1) 바이트인지 확인합니다. 값이 없는 칸은 연속 필드면 float32 NaN, 범주 필드면 `no_data: true` 인 범주(굽기 코드는 번호 255, 색은 `nan_rgb`)입니다. 형식이 틀리면 지구본을 그리지 않고 이유를 화면에 보여 줍니다.

## 검사

```sh
uv run pytest -m godot tests/test_engine.py
```

직접 돌릴 때는 반드시 `--headless` 와 임시 HOME 을 씁니다(`README.md` 의 '검사' 참고).

```sh
G=.tools/godot-net/Godot_mono.app/Contents/MacOS/Godot
dotnet build engine/Bpcg.Engine.csproj
H=$(mktemp -d)
HOME=$H $G --headless --path engine --import
HOME=$H $G --headless --path engine res://Tests/globe_smoke.tscn -- --baked-dir=<굽기 폴더> --expect-globe
```

`Tests/globe_smoke.tscn`(`Tests/GlobeSmokeTest.cs`) 은 성공하면 `BPCG_GLOBE_OK`(자료가 없으면 `BPCG_GLOBE_OK (no data)`), 실패하면 `BPCG_GLOBE_FAIL: <이유>` 를 찍습니다. 보는 것은 다음과 같습니다.

1. 면 메시 6 개, 면마다 꼭짓점 (N+1)², 삼각형 2N², 앞면이 바깥. 꼭짓점 (r, c) 의 UV 가 (c/N, r/N) 이고 방향이 문서의 사상과 같음(대각선 밖 꼭짓점도 보므로 행·열이 바뀐 메시는 실패)
2. 면 경계 꼭짓점이 이웃 면과 비트 단위로 같고 고도 차 0 (틈 없음)
3. 모든 레이어를 고를 수 있음: 면 재질의 텍스처와 `categorical` 이 바뀌고, 범례 제목·버튼·범주 수·넓이 몫 잣대 글·색 막대가 따라옴. 텍스처 픽셀 색 = 색표(저장 값), 알파 = 텍셀의 종류. `point_markers` 레이어는 0 이 아닌 칸 수만큼 점이 있고, 다른 레이어로 바꾸면 사라짐
4. 방향 → 칸 → 칸 중심 → 칸 왕복 (무작위 방향 200 개, 무작위 칸 200 개)
5. 검사 안에서 따로 짠 역사상으로 읽은 `.bin` 값과 `value_at` 이 같음 (범주·연속)
6. 히어로 방향의 위도·경도가 `globe.json` 과 0.01° 안, 핀이 지표에 수직으로 섬, 과장을 바꾸면 따라옴
7. 고도 과장(한계 1 ~ 100, [ ] 키), 강·호수·경위선(R, K, L), 강 등급(Shift + R), 그늘·대기 빛(G), 숫자 키, Tab. 문턱 아래 강 칸을 가리키면 '그리지 않음' 이라고 읽음
8. 카메라: 화면 가운데를 고르면 카메라 쪽 방향, 확대 한계, 날아가기, Space
9. 클릭 고정 상자에 모든 레이어와 겹쳐 보기가 이름과 함께 나옴, Esc 로 풀림

pytest 는 네 번 돌립니다: 엔진 안에서 만든 tiny 실행의 지구본, 굽기 코드와 상관없이 위 형식만으로 쓴 작은 해석적 자료(`tests/globe_fixture.py`: NaN 칸, 로그 필드, 범주 14 개, `color_break`, 점으로 찍는 드문 범주와 rgb 가 null 인 범주·'값 없음' 범주 255, 문턱 아래 강 등급), 빈 굽기 폴더('자료가 없습니다'), `.bin` 크기가 틀린 자료('읽지 못했습니다').

## 한계

- 값은 L0 칸 크기만큼만 곱습니다. 지구본 칸이 더 고와도(tiny 처럼 L0 가 거칠 때) 같은 L0 값이 여러 칸에 걸쳐 보입니다.
- 그늘은 삼각형마다 평평한 면 법선이라, 아주 가까이 당기면 삼각형 무늬가 보일 수 있습니다.
- 값 없는 칸이나 `color_break` 의 경계에서는 보간하지 않고 가장 가까운 텍셀을 쓰므로, 해안선과 값 없음 경계가 칸 크기만큼 각져 보입니다(범례에 없는 색을 만들지 않으려는 것).
- 드문 범주의 점은 칸이 있는 자리만 알려 줍니다. 점 크기는 넓이와 상관없고, 칸이 2 만 개를 넘으면 찍지 않습니다(그때는 텍스처 색만).
- 지구본과 회랑 사이는 M 키로 오갑니다(지구본 → 회랑은 `GlobeMain.cs`, 회랑 → 지구본은 `Main.cs`). 회랑에서 돌아오면 지구본은 처음 자리(히어로 유역)에서 다시 시작합니다.
